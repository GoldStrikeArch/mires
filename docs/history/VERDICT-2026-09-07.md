# Verdict: rustc_codegen_js

The original three compiler rounds were GO. The generic optimizer checkpoint below remains opt-in.

- **Stage 0 (spike), 2026-07-29 morning**: proved a rustc codegen backend can lower
  monomorphized MIR to correct JavaScript. 8 golden tests, a browser demo, ~1,400 lines
  of lowering. (Original spike verdict preserved in git history.)
- **Stages 1+2, 2026-07-29**: the language core and the output-quality stack.
- **Stage 1.5, 2026-07-29 evening**: the `{buf, off}` pointer model. See below.

## Stage 1.5: the pointer model — the "R1 risk" is retired

The one problem the original research flagged as having no clean precedent — raw
pointers in a structural value model — is solved and proven. A pointer is a **slot**
(`{buf, off}`, offset in pointee units) with scaled/window/address forms for the byte
views, casts and provenance-free cases; synthetic WeakMap addresses make `is_null`/
`is_aligned`/`fmt::Arguments`' tag bit guarantees rather than accidents.

What that unlocked, all green in `examples/core-tests/`:

- **`core::fmt`**: `write!` with the full format-spec surface (radix, width, fill,
  precision, named/captured args, user `Display` impls) — real formatting machinery,
  template bytes and erased argument vtables included, running as JavaScript (11_fmt).
- **`slice::iter()`** and the adapter chain, `iter_mut`, slices of structs and ZSTs
  (12_slice_iter) — green on the first compile after the model landed.
- **`sort_unstable`** on `[i32]`/`[u64]`/structs at every length — the whole ipnsort
  tree: insertion sort, sorting networks, quicksort partitioning through
  `MaybeUninit` scratch buffers and gap guards (13_sort).
- **`str`**: byte views (the old silent `as_bytes` miscompile is fixed and pinned),
  `chars`/`char_indices`, comparisons, `starts_with`, `get(a..b)` (14_str).
- **`15_ptr`**: the model's own unit test — null/dangling round trips, `ptr::eq`
  across independently-taken pointers, overlap-safe copies, offset arithmetic.

**Surviving zombies in `core`: 5,600 -> 20 (-99.6%).** Suite: **33/33** runtime +
**14/14** emit goldens, green in every flag mode. Minify gzip cuts 32-58%.

Seven backend bugs were found by the test workstream and fixed by the backend
workstream during the wave — including three SILENT wrong answers (`addr()` losing
the element size, whole-aggregate writes through boxed pointers dropped, quicksort
aliasing struct elements through the partition) — exactly the class of bug this
round existed to make unshippable. Hoisted constants shipped but default OFF on
measured evidence (incompressible hash names lose 1-5% gzipped); the real win was
`--remap-path-prefix`, now unconditional.

Honest remainder (documented in `examples/core-tests/README.md`): `&s[a..b]`/
`contains` (an `[AsciiChar] -> str` cast in the panic path), reverse `rfind`
(`memrchr`'s word-at-a-time `align_to`, a deliberate run-time refusal),
`NonNull::dangling` via `Alignment`, `read_unaligned`, and ~5 one-off transmutes.
`alloc` remains the next representation-design round.

## Stage 1: the language core

- **Zombie system + DCE as one graph** (rust-gpu's model): unsupported constructs record
  deferred errors that fire only if reachable from the program's roots, with
  `required by` chains; unreachable items vanish. The proof: `library/core` compiles
  through the backend in **6.4 s** with **one patch** (panic paths carry static messages
  instead of `fmt`), leaving **5,600 zombies inside core, all silent**. A program that
  reaches one (e.g. `write!`) gets a precise chain from the `core::fmt` internals up to
  its own `rust_entry`.
- **Language surface**: drop glue (recursive, rustc-synthesized), `dyn Trait` with
  array-shaped vtables at rustc's exact slot indices, supertrait upcasts, slices as
  `{buf, off, len}` with shared-buffer subslices, statics (provenance-aware constant
  reading), i64/u64/i128 as BigInt with the full cast matrix, `usize` genuinely 32-bit
  (wasm32 target: correct by construction), saturating float casts, `Math.fround` f32,
  a 166-key intrinsics table, full `#[track_caller]`, representation-aware `transmute`.
- **Real-core test suite**: Option/Result combinators and `?`, `Ordering` and derived
  `Ord`, the whole Range-iterator adapter chain, slice indexing and patterns,
  wrapping/checked/overflowing/NonZero arithmetic, `mem::swap`/`replace`/`Drop` order,
  `&dyn`/`&mut dyn`, closures through `impl Fn` bounds, and a `#[track_caller]` panic
  resolving to the user's `unwrap()` line.

## Stage 2: the output-quality stack (the jsoo playbook, ported)

- **Structurizer** (standalone crate, 48 tests incl. a randomized dual-interpreter
  property test): dominator-tree relooping with `shrink_loops`, DTree switch synthesis
  (`===`/range/`(x-lo)>>>0<len` forms, sign-biased value ordering), dispatch fallback for
  irreducible graphs. Integration alone cut emitted bytes **41.8%**.
- **Expression queue + destination passing**: MIR's three-address temporaries fused into
  expressions across block boundaries; declared locals **-83%** (5.9x, jsoo's promised
  3-5x), emitted lines -35%, `while`-loop recovery. Queue-off reproduces prior output
  byte-for-byte for bisecting.
- **Readable names**: locals and params from MIR `VarDebugInfo` (empirically verified to
  survive `-Cdebuginfo=0` and inlining), item names as sanitized def-paths with
  deterministic hash suffixes.
- **Source maps v3**: statement-granularity, byte-identical JS guaranteed (a printing
  no-op marker, not an AST wrapper), VLQ-validated by an automated decoder, working
  across crate boundaries (stepping into `core/src/iter/range.rs` from an rlib),
  `names` table for original Rust identifiers, `ignoreList` blackboxing for glue,
  DevTools recipe in the demo.
- **Minifier**: whole-program item rename over the linker's own table plus a
  frequency-sorted local renamer and compact printer. **Gzip: -31% to -58%** vs readable
  (`scripts/measure-size.sh` table in CONTRACT.md). Deterministic, `node --check`-clean,
  exports preserved.

## Known boundaries (deliberate, documented, zombie-guarded)

1. **Raw pointer arithmetic** — the dominant blocker: `slice.iter()` and everything on
   it (`sort`, `contains`, `copy_from_slice`), `split_at`, `str` beyond len/printing.
   The designed fix is the `{buf, off}` universal pointer slot (stage 1.5 decision,
   deferred by plan).
2. **`format!`/`Debug`/`Display`** — blocked on (1) plus the one core patch; `&dyn
   Display` vtables would otherwise drag all impls into every program.
3. **`alloc`** (Box/Vec/String) — deferred to the representation-attributes design
   round, per plan.
4. f16/f128, SIMD, real threads, `TypeId` equality.

# v2 disposition: Phases 0–3 (2026-08-17)

**STATUS: the compiler works; the size gates do not pass.** Everything above is v1. This section
is the integrated verdict on `spike/rustc-codegen-js-v2`.

## What v2 is

One idea: **move the lowering out of the compiler and into the linker.** v1 is a rustc backend that
prints JavaScript. v2 splits it in two — a *producer* dylib that lowers MIR into a canonical IR
(JIR-S) and writes binary object files (format 20), and a *consumer* binary (`jsc-link`) that reads
those objects and produces the program. The consumer needs no rustc, builds on stable, and has an
ordinary `cargo test`. Every object carries **both** spellings of every item it defines — v1's
printed text and the item's JIR-S body — so which one a program is printed from is a per-item link
step decision (`js-lane=baseline|jir|shadow`), and an item the new lowerer declines silently keeps
v1's text. That fallback rule is what made each phase shippable on its own.

Phase 3's two failures have one shape and it is not a defect in what landed: what is left in the
hot loops is iterator/`Option` plumbing that the escape analysis excludes **by design** (references,
slice views and raw pointers are not candidates; an `Option` merged across a loop switch has two
variants), and the byte gap is unrolled bounds checks and their `Location` literals. Both need
`next()` inlining with late materialization, which is Phase 5 machinery. The plan said to record
that ceiling and stop for review rather than widen scope, and that is what was done.

## The external review's blocker, and its status

An external review of Phase 3 found one **miscompile** — not a size or a policy question:

* **`$rN` spill-register name collision.** The flat direct-call ABI writes a callee's extra results
  through link-generated `$rN` registers. Nothing stopped one of those names from colliding with a
  name already in the program, and a collision is a silently wrong program. **Fixed in this round**,
  with `examples/core-tests/67_spill_name_collision.rs` as the differential fixture. The earlier
  statement in `checkpoints/phase-3.md` that "nothing found is a miscompile" was wrong when it was
  written and is corrected there.

Three further findings, all fixed in the same round and none of them a miscompile:

* **Four test suites silently dropped `js-opt`.** `emit-test.sh`, `module-test.sh`, `dts-test.sh`
  and `extern-test.sh` rebuild their own argument lists and forwarded only `js-lane=jir`, so
  Phase 3's rows for "these suites on `js-opt=on`" were `off`-lane runs reported as `on`. Each now
  has an explicit `*_OPT_MODE=off|report|on` control that builds its own keyed sysroot and prints
  the mode it compiled in, `matrix.sh` gained a `lane-suites-opt` mode that runs all four, and the
  corrected counts are in `checkpoints/phase-3.md`.
* **`bytes_min` was not what it claimed.** It is the "what would this one item cost minified"
  number the Murmur size gate divides by, and it only shortened locals when the whole build
  minified — which the port build does not. It is now measured on a locally shortened clone
  (`rcgjs_object::minify::shorten_locals_for_measurement`), so the ratio is apples to apples.
* **The alloc metric over-claimed and under-covered.** It is not a count of allocations: it is a
  count of the *places* the emitted JavaScript builds a fresh object, and its `in_loop` figure only
  saw natural loops, so an irreducible cycle read as depth 0. Every block on a cycle now counts,
  record-shaped pointer views (`{ buf, off, len }` and friends) are counted as their own reported
  `view` kind, and the docs say what the number is.

## Disposition

v2 is a **GO as a compiler** and a **NO as a size win**. The lane is correct (90/90 runtime, three
browsers with zero differences on both FingerprintJS ports, a clean fuzzer, a clean shadow
differential over 111 fixtures), it is deterministic, it composes with every flag mode, and on the
wire its `js-opt=on` is now *ahead of the frozen v1 optimizer's* on both ports. It does not meet
the −5 % byte gates the plan set, and the remaining bytes are named and attributed rather than
unexplained. `js-opt` stays opt-in and `js-lane` stays `baseline` by default.

### Phase 12 structural and exact-storage candidates (updated 2026-09-03)

Finished-JIR SROA now forwards direct aliases of stable, dominating SSA values through the same
conservative pass that already handled fresh object roots. An unassigned parameter or a compiler
local written exactly once may be the direct source; alias chains canonicalize transitively.
Reassigned locals, replaced-field snapshots, shadowed names, and verbatim JavaScript still decline.
Two focused tests pin the positive chain and mutable-source counterexample. Phase 12F extends that
proof to connected direct-copy locals with exactly one stable external anchor. Non-copy writes,
unknown or multiple anchors, and unsupported property snapshots decline. A 32-byte compact-function
floor rejects substitutions too small to survive compression reliably.

The Phase 12F result put the seven Murmur items at 7,452 bytes. Phase 12G implements its measured
tail opportunity as a generic finished-JIR pass. Exact rustc diagnostic-item identities distinguish
`SliceIter`, `Enumerate`, `Take`, and `Skip`; a private, non-escaping
`Enumerate<Take|Skip<SliceIter<u8>>>` driver becomes a checked scalar cursor only after its source,
length, loop SCC, backedges, and exits are proven. An independent witness rolls a failed rewrite
back to the original item. The witness binds every transformed loop and its exact cursor, guard,
borrow, index, backedge, and exit; lane-report schema 15 separately records opportunities and
cursors retained in final output. Fixture 105 pins both adapters, early break, four hard declines,
and a targeted slice-witness fault.

The implemented pass removes 820 graph bytes, reaching **6,632 bytes** with zero JIR fallback,
