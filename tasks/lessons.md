# Lessons

- 2026-11-08: The user requires delegated execution: implementation work runs in subagents on Opus 5.5 at xhigh effort, and every stage is checked by a separate verifier subagent on Fable 5.1 at high effort. Do not present a plan without an explicit execution model; do not implement stages inline in the main session.
- 2026-11-08: `scripts/test.sh` byte budgets (`.maxbytes`) are baselined against the default cleanup-off mode and are only waived when JS_EXTRA_ARGS contains js-minify / js-source-map / etc. Under `js-lane=jir js-opt=on js-cleanup=on` 89/138 fixtures fail on budget alone at HEAD. Use `JS_EXTRA_ARGS="js-profile=release-balanced"` (budgets waived) as the behavioural gate, and treat the explicit jir+opt run as behaviour-only (compare "over budget" rows against the baseline binary). Do not specify a gate command in a brief without having seen it pass at baseline.
- 2026-11-08: subagent worktrees are created from the current HEAD at spawn time; always state the expected HEAD in the brief and have the agent verify `git rev-parse HEAD` first.
- 2026-11-08 (correction): `scripts/test.sh` does NOT waive budgets under `js-profile=release-balanced` either — the waiver matches the raw JS_EXTRA_ARGS string and the profile is only expanded in sysroot-cache.sh. Under release-balanced 22 fixtures fail on budget alone at baseline. Gate rule stands: compare test.sh tables behaviourally against the baseline binary; never assume a waiver.
- 2026-11-08: a fix that turns a crash into a silent wrong answer is not fail-closed. Verifiers must probe the adjacent observations (here: every pointer form to the repaired value), not only the reported case.
- 2026-11-08: an emitter helper that branches on an expression's SYNTAX (`ref_to_raw`: `x.f` → field slot, named value → box) breaks the rule that an inline value means the same as its name; fusion then changes semantics. Lowering must consume values by meaning (type/place facts), never by spelling. A "pass" that depends on fusion being disabled (Invoke-bearing bodies) is an accident, not coverage — test both fused and unfused shapes.
- 2026-11-10: execution model updated by the user: implementers stay Opus 5.5 xhigh; verifiers are now Fable 5.2 at xhigh effort (Agent model "fable", effort "xhigh"). Verifiers died twice on exhausted usage credits (2026-11-08): when a verifier fails for an infrastructure reason, re-spawn it with the same brief; never treat an unfinished verification as a pass.
- 2026-11-10: a subagent that was denied a permission (here `git stash drop`) and asks the orchestrator to do it instead must be refused and surfaced to the user, not obliged.
- 2026-11-10: Stage 1b failed verification three times (round 1: runtime regressions; round 3: four silent wrong-value regressions + perf + address exhaustion). Cause on my side: one work item bundled a cross-cutting semantic MODEL (write-through stores, detached moves, anchored addresses) with the small bug fixes that actually blocked the merge. Rule: when a change is needed to unblock a merge, scope the brief to the minimal fix that the failing fixtures require and prove it by mutation; a model redesign is its own work item with its own design review, never a merge blocker. After a second fail, split instead of looping.
- 2026-11-10 (user decision): when verification finds a limit that needs an unsupported `unsafe` construct or that predates the change, do not block the stage and do not silently widen the acceptance criterion: document it (CONTRACT.md + the "Accepted limits" list in tasks/todo.md), tell the user, and decide the fix later. Verifier briefs should say so up front: such cases are listed separately from the verdict; a case reachable in safe Rust, or one where every value has its normal representation, is still a fail.
- 2026-11-10 (user, later the same day): verifiers are now spawned as Fable 5.2 at HIGH effort (Agent model "fable", effort "high"), no longer xhigh. Implementers stay Opus 5.5 xhigh. A resumed agent keeps the effort it was spawned with, so a re-check after this point is a fresh verifier at high with the earlier verifier's scratch directory and report named in its brief, not a resume of an xhigh one.
- 2026-11-11: `jsc-link` embeds `runtime/shim.js` (`include_str!` in `plan/cost.rs`), so (a) after any shim change the linker must be rebuilt before compiling on the optimized lane, and (b) optimizer decisions are scored against the shim's text, so an unrelated shim edit can flip flat-ABI and representation choices in other programs. Briefs for shim changes must ask for the list of programs whose output changed and what flipped.
- 2026-11-11: gates and extent matrices must include the settings the package and workload builds actually use (`JSC_RUST_MIR_INLINE=on`, `JSC_RUST_OPT_LEVEL=z`); the 1c fix passed five configurations and still failed under MIR inlining.
- 2026-11-11: A/B timing taken on this machine at load above roughly 20 is unusable (±40% on byte-identical code). With several agents building at once, ask for timing only as a note, and re-measure on a quiet machine before any runtime claim.
- 2026-11-11: parallel implementers each picked "the next free" fixture number and collided (121–126). Assign every agent a distinct fixture-number range in its brief.

- 2026-11-12: disk. Each agent worktree builds its own compiler and sysroots (10–57 GB each) and verifiers copied the whole source tree again for a "before" compiler; the volume reached 94%. Briefs now point verifiers at one shared base build and tell every agent to delete reproducible build outputs before finishing. After a verifier reports, the coordinator removes `target/` and `build/` from that verifier's worktree (git-ignored, reproducible) with literal absolute paths; a removal built from shell variables is blocked by the safety check, correctly. Never touch the preserved round-1 worktrees.
- 2026-11-13: (my own error, found by an implementer) I told the user "all 31 host bindings are `extern "C"`" from a grep of the macro crate; 30 of those hits were the macro's input syntax in tests. The macro emits Rust-ABI marker functions. Rule: a claim about what a macro or code generator emits is checked on its expansion (`-Zunpretty=expanded`) or on MIR, never on a text grep of its sources. Also: the harness refuses subagent writes of `REPORT.md`-style files; briefs ask for `results.json` plus the final message, not a report file.
- In an agent worktree, rebuild the compiler only with `bash scripts/build.sh --locked` (never a bare `cargo build --release`): the bare build produces a different backend dylib, which changes the producer hash and every sysroot cache key (2026-11-14, my own slip while re-running the unwind-mode fix; restored before measuring). Always `export CARGO_INCREMENTAL=1` first: a sysroot built without it has different crate hashes and breaks byte comparisons.

- 2026-11-17 (correction of the 2026-11-14 `CARGO_INCREMENTAL=1` rule, found by the Round 3 gates verifier): the qualification receipts (both `main` and Round 3) are built with `CARGO_INCREMENTAL` UNSET, and `-Cincremental` turns off rustc's MIR inliner, so the emitted JS differs (compact 48,221 → 48,242 gz). The sysroot cache key does not record the setting, so an incremental and a non-incremental sysroot share one key. Rule: match the setting of the baseline you compare against (non-incremental for anything compared with a receipt), use the same setting on both sides of every comparison, and never reuse a sysroot directory across the two settings. The receipt's binary hashes are also path-bound (the dylib embeds the absolute worktree path); jsc-link reproduces across worktrees only when built non-incremental.
- 2026-11-17: minisearch timing in `timing-cell.mjs` is bimodal per module instance (each arm lands at ~0.26 or ~0.35–0.42 ms per call regardless of build; A/A 0.62–1.37), so its per-cell ratios and the [0.88, 1.12] A/A band are meaningless for it; compare fast-mode values pooled over many cells. JSC murmur is bimodal too (7–25 µs). The qualify script's A/A gate is not enforced (`timingPassed` only means checksums agreed).
- 2026-11-17: after `build.sh` in a checkout, `SKIP_BUILD=1 scripts/test.sh --require-core` fails ("core suite skipped: no sysroot at build/sysroots/<key>") whenever no keyed sysroot exists for the current dylib, mode and args. `test.sh` builds a missing keyed sysroot itself only when `build/sysroot` points at a wasm32 sysroot. The main checkout's link pointed at an unwind one, so it did not. Rule: before running a gate with `SKIP_BUILD=1`, run `SKIP_BUILD=1 JS_EXTRA_ARGS=<the gate's args> [JSC_PANIC=abort] bash scripts/build_sysroot.sh` once per mode (with `CARGO_INCREMENTAL` unset). A cache hit costs nothing.

Rule: every implementer and verifier brief says "do not spawn subagents; the coordinator owns the agent budget".
