# idb 8.0.4

The browser matrix exercises the package's promise-based IndexedDB API. Each call opens a uniquely named version 1 database with `openDB`, creates the `rows` store keyed by `id` and a non-unique `byGroup` index, and awaits `deleteDB` after closing the connection. Every operation uses real IndexedDB in the browser's origin. Node has no native IndexedDB in the configured runtime.

Each `batches` entry starts a read/write transaction. It issues a request for each record in order with `tx.store.put`, or `add` when the batch has `add: true`. The optional `abort` flag calls `tx.abort()` after the requests are queued. The standalone fixtures use a numeric `id`, string `group` and string `value`. Explorer also exercises string primary keys, replacement and cursor ordering. The completion promise and all request promises are observed independently, including on uniqueness violations and explicit abort. A successful request reports its key, a completed transaction reports `done` and a rejection reports `!` followed by its DOM exception name.

One readonly transaction reads the numeric `keys` from the store and string `groups` from the index in input order. Its cursor follows the store or index according to `index`, ascending or descending according to `reverse`. Optional `only` supplies an equality range on the selected source. `step` is a positive integer. A step of one uses the cursor's asynchronous `continue` method, a larger step uses `advance`. The output is a four-element JSON array of transaction outcomes, lookup values (or null), index lookup values (or null) and cursor triples containing key, primary key and stored value. The benchmark includes 64 writes, 67 independent reads and an index traversal.

The contract covers request promises, transaction completion, store and index methods, promise-returning cursor movement and database lifecycle. The matrix checks these observable operations without exposing JavaScript Proxy identity outside the language boundary. Elm's IndexedDB host is included in its reported source and artifact size.

`expected.json` records the pinned browser package's complete outputs. Run `node verify.mjs chrome rust` (or another built language and browser) in this directory to exercise two overlapping calls per case, compare their results with this capture and verify the browser's database inventory returns to its initial state. `node verify.mjs chrome reference --capture` regenerates the fixture from the published package.
