# @noble/hashes 2.4.0

The selected API includes SHA-256, SHA-512, SHA3-256, Keccak-256, BLAKE2b, BLAKE2s and HMAC-SHA-256. Each operation returns its complete lowercase hexadecimal digest. SHA3-256 and Keccak-256 use different domain separators. All hashing runs in the port language.

Each input names an `algorithm` and supplies either a one-shot `bytes` array or a `chunks` array for incremental `create().update().digest()`. Every input byte is an integer from 0 through 255. Zero-length messages and empty updates are included. The optional positive integer `repeat` repeats the chunk sequence on the same hash state. When both are present, `bytes` is hashed and `chunks` and `repeat` are ignored, as `reference.mjs` does. The return value is a string. Input arrays keep their original contents.

HMAC takes a required byte-array `key`, including an empty key. BLAKE2 accepts optional `dkLen`, `key`, `salt` and `personalization`. For BLAKE2b the digest and present keys range from 1 to 64 bytes, while salt and personalization have exactly 16 bytes. BLAKE2s uses limits of 32 and 8 bytes respectively. A digest length that is not a safe integer (a fraction, or beyond 2^53), a negative one or negative zero, an out-of-range one (including values past 2^32 that a 32-bit conversion would wrap into range), and an unknown algorithm name throw. npm ignores `dkLen`, `key`, `salt` and `personalization` on SHA-256, SHA-512, SHA3-256 and Keccak-256, and `dkLen`, `salt` and `personalization` on HMAC, even values BLAKE2 rejects. Each call starts with fresh state.

An optional field is either absent or of its documented type: `dkLen` a number, `repeat` a positive integer, `key`, `salt` and `personalization` arrays of bytes. `null` is outside the domain. npm throws for some null fields (a null `key`, `salt` or `personalization` fails `Uint8Array.from`, a null BLAKE2 `dkLen` fails `anumber`) and uses others as values (a null `repeat` runs no updates), so a port may treat `null` as absent.

The three benchmark cases hash exactly 1 MiB each, in 256 updates of a 4,096-byte block. The variant changes four bytes of that block while preserving the number of compression rounds. The canonical reference calls the pinned npm package directly.

The corpus covers block and padding boundaries, HMAC key normalization, domain separation, short keyed BLAKE2 digests, invalid parameters, and incremental chunk splits. The 2026-11-20 review added digest lengths past int32 and past 2^53 and negative zero (the generator writes it as `-0`, which `JSON.stringify` cannot), several invalid options at once, the options npm ignores, HMAC keys around the block and digest lengths, unknown names close to real ones, and large inputs: a 2 MiB BLAKE2b message in one update, a 2 MiB message streamed in 4,099-byte updates for every algorithm, 200,000 updates of 0 to 3 bytes on one state for every algorithm (`repeat` 50,000 over four chunks), and an HMAC `chunks` array 200,000 entries wide. The one-shot message uses decimal-digit bytes, about two JSON characters per byte, which keeps `corpus.json` near 5.6 MB. Run `node generate-corpus.mjs` here to regenerate it. Run `node verify.mjs <language>` after building a port for the digest vectors and a length-by-length comparison.

`known-answers.json` contains selected byte-oriented CAVP short-message vectors, keyed and unkeyed BLAKE2 answer vectors, the empty Keccak-256 digest, and RFC 4231 HMAC-SHA-256 test case 1.
