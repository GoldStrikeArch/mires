# big.js 7.0.1

Each input supplies a list of independent decimal operations in `cases`, and an optional positive integer `repeat` count; an absent or null `repeat` runs the list once. Each operation constructs a fresh decimal from `x`, a decimal string or a finite JSON number. The sign and coefficient may begin with a minus and include a decimal point and signed exponent. Number inputs use big.js's own conversion at the language boundary: JavaScript's standard number-to-string conversion, except that −0 becomes `-0` (a zero's sign never prints, so this is unobservable).

`plus`, `minus`, `times`, `div` and `cmp` take a second decimal in `y`. `pow` takes an integer exponent `n`. `sqrt` and `toString` need only the receiver. `round`, `toFixed`, `toExponential` and `toPrecision` accept an optional integer `n` and an optional rounding `mode`; `n` and `mode` are absent or JSON numbers. JSON null for them is outside the domain by a boundary decision, not an upstream limit: npm throws there deterministically (`Invalid decimal places`, `Invalid precision`, `Invalid exponent` or `Invalid rounding mode`), but several languages' interop does not tell null from undefined, and those ports read it as absent. The constructor's decimal places and rounding mode are configured independently for each case with `dp` and `rm`; absent or null selects the defaults 20 and 1, as the adapter's `??` does. Any other number reaches big.js unchanged, which validates `Big.DP` only where it divides (`div`, `pow` with a negative exponent, and `sqrt`, which checks `DP + 4`) and `Big.RM` only where it rounds. Options past int32 and past 2^53 fail those checks rather than wrapping. Rounding modes 0 through 3 select round down, half up, half even and round up. Exponential display thresholds are the upstream defaults of −7 and 21.

The result joins all decimal strings, comparisons (-1, 0, 1) and exact upstream error messages with newlines in execution order. The benchmark runs 10,000 mixed operations on 50-digit operands, returning each value. The corpus includes scientific notation with exponents beyond signed 32-bit bounds and beyond 2^53, signed zeros, negative decimal places, ties, all rounding modes, error precedence, and generated operands of up to 20,000 decimal digits. An exponent is one `Number()` parse of its signed digits, so it rounds once past 2^53 and is Infinity past the double range; Infinity and NaN (Infinity − Infinity) exponents are in the domain wherever upstream finishes.

The domain excludes operations that upstream never finishes, that exhaust memory, or that end in a host error rather than a value or a big.js error (the RangeError of an array past the host's length limit). Three kinds are reachable:

- **Square roots whose Newton-Raphson loop never stops.** Upstream iterates `r = 0.5 × (r + x / r)` at `DP + 4` decimal places and stops when the first `r.e + DP + 4` digits repeat. For many operands near and below the last requested place the iteration cycles instead, in every rounding mode (`sqrt` of `4e-15` at `dp` 0 and `rm` 3, or of `6e-44` at `dp` 2 and `rm` 0). Inexact roots of operands with large exponents cost time quadratic in the exponent, because each division at `DP + 4` places produces about `x.e / 2 + DP` digits from a divisor as long; at exponents in the millions they do not finish. The ports run the same iteration and do not stop either; the corpus generator keeps only square roots on which upstream's loop stops within 200 iterations with a value or a big.js error.
- **Host array limits.** A sum or quotient whose digit array passes the host's length limit throws `Invalid array length`. For example, `sqrt` of `4e-4294967298` at `rm` 3 adds an estimate near 10^-2147483649 to a quotient near 10^-4, prepending about 2^31 zeros. The same square roots at `rm` 0, 1 and 2 are in the domain: there the re-estimate exponent `((e + 1) / 2 | 0) - (e < 0 || e & 1)` is −2^31 − 1, an int32 minus a double.
- **Unbounded digit loops.** Sums across an infinite exponent difference, fixed notation of an infinite or huge positive exponent, `toFixed()` without decimal places of an infinite negative exponent (stringify's `for (; ++e;)`), and inexact quotients with an infinite quotient exponent.

`upstream-vectors.json` retains selected literal assertions, expected strings and source line numbers from [the upstream v7.0.1 method tests](https://github.com/MikeMcl/big.js/tree/v7.0.1/test/methods). Each method's file has the same name as its operation.

The standalone verifier checks the fixed answers in `exponent-vectors.json` and compares arithmetic and rounding against the pinned package around positive and negative powers of two. Benchmark variants vary both 50-digit operands while retaining their leading and final digits.
