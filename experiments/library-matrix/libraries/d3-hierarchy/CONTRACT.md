# d3-hierarchy 3.1.3

Inputs with `source: "hierarchy"` supply a nested `data` object with an optional string `id`, optional numeric `value` and optional `children` array. Flat `rows` with `source: "id"` use the default stratify id and parentId accessors. With `source: "path"`, each row has a string `id` path. Stratification preserves input order, escaping, implicit ancestors, root trimming and upstream errors. Each node aggregates its own weight and its children’s values. A weight of negative zero contributes positive zero. Setting `sort` to true sorts children stably by descending aggregate value.

Operations are hierarchy, stratify, iterator, tree, cluster, treemap, pack and partition. The numeric width and height specify layout size. For tree and cluster the boolean nodeSize selects fixed node spacing. Treemap supports the squarify, binary and sliceDice tilers. Numeric padding applies to treemap, pack and partition. The boolean round selects integer rounding for treemap and partition, by `Math.round`.

Each output row starts with the id, parent id (null for the root), depth, height and aggregate value. Tree and cluster append x and y, pack appends x, y and radius, and rectangular layouts append x0, y0, x1 and y1. The iterator operation returns breadth-first order. All others use pre-order. Equality includes every coordinate as an exact JavaScript number, including NaN and signed zero.

The aggregate of a leaf with weight `-0` is positive zero. The corpus also has widths and heights of `-0`, which reach `Math.min` in pack and the ratios of squarify. The browser checker reads literal `-0` from the corpus. The Node checker hands its cells the corpus through `JSON.stringify`, which writes `-0` as `0`, so its reference digests for the `-0` sizes differ from the browsers' (the summary's `referenceStableAcrossEnvironments` is false for those cases alone). The standalone Node verifier reads the same file directly: it uses `Object.is` on both the input weight and the output aggregate, and compares every case with a `-0` in its input exactly. This preserves the sign through the test, which ordinary JSON serialization would erase.

## Domain

Inside these bounds every port matches npm exactly; the corpus has cases at each of them.

- **Ids.** When present and non-null, ids are strings and well-formed UTF-16. For `source: "path"`, every row has a string `id` (d3's template-string coercion in `normalize` is not ported). The Rust, js_of_ocaml and GopherJS ports read stratify ids as UTF-8, which replaces a lone surrogate by U+FFFD (GopherJS also swallows the unit after a lone high surrogate), so distinct ids can merge in path stratification. An absent, `null`, or empty id names no node in stratify, as in d3.
- **Null fields.** Matching d3 (`parentId != null`, `d?.value ?? 0`, `children(d)` falsy, `n.id ?? n.data.id`), `null` is accepted wherever a field is optional or absent: `parentId: null` marks a root in `source: "id"`, `children: null` marks a leaf, `value: null` contributes `0`, and a missing or `null` `id` is emitted as `undefined` or `null` respectively, matching the reference's `n.id ?? n.data.id`.
- **Weights.** `value` is a number when present and non-null (not a string: d3's `+value` coercion is not ported). Weights may be negative, zero, subnormal or near the largest double. Aggregates may then overflow to ±Infinity, and a subtree that sums +Infinity and −Infinity has a NaN aggregate. Every port tests numbers as JavaScript does: `value ? … : y1` in the binary and squarify tilers, squarify's `!sumValue`, pack's `if (d2)` and the `|| 0` coercions are false for NaN as well as for zero.
- **Sort with NaN aggregates.** With `sort: true`, no node with three or more children may have a child with a NaN aggregate. Even a single NaN child among three or more siblings makes the comparator `b.value - a.value` inconsistent (NaN counts as 0 in Array.prototype.sort, so the NaN node compares equal to every sibling while the others are ordered), and ECMAScript leaves the resulting order implementation-defined: npm itself produces different orders in V8 and SpiderMonkey, and ports with their own stable sort (Rust, OCaml, Scala.js, Go) differ from V8 too. With two siblings, a NaN aggregate stays in-domain and preserves their input order, matching npm. Infinite aggregates are fine: Infinity − Infinity is NaN, but equal infinities are equal anyway.
- **Sizes and padding.** Width, height and padding may be zero, negative, −0 or past 2^53. Pack with a zero or negative size and padding may throw (d3's "something is very wrong" in the enclosing basis), and then every port throws too.
- **Pack weights.** In a pack layout, every leaf's value is at most 1e300. Beyond that, squared radii overflow to Infinity: npm then throws (the two `pack-overflow-*` cases, kept because a port hung on them), or, for some trees with several such leaves, retries the front chain forever.
- **Depth.** hierarchy() and every traversal run on explicit stacks, as in d3, so nesting depth is unbounded. The checker structured-clones each input, which fails above about 1,500 nesting levels, so the corpus nests `data` 1,000 levels deep and carries deeper trees as flat rows (a 10,000-level chain of rows, and a 3,000-level chain of imputed path ancestors). `verify.mjs` builds a 10,000-level nested chain directly.
- **Binary tiler.** With `tile: "binary"`, a node has at most 1,000 children. binary.js recurses once per split, up to once per child: zero weights split one child off at a time. npm itself overflows the stack near 5,000 such children in Node, and the Rust port near 3,000.

The two timing cases lay out all 10,000 nodes as a treemap and as packed circles. Each timing variant changes the data in every subtree while preserving the tree shape. Run `node generate-corpus.mjs` to regenerate the corpus. The upstream flare hierarchy is included with its original node names and weights. [Upstream fixture](https://github.com/d3/d3-hierarchy/blob/41f11f82647566c90150272210c50188dec4071b/test/data/flare.json)

After building a port, run `node verify.mjs <language>` here to check the official 252-node circle-pack fixture, 576 further exact layout comparisons on independently generated trees, the corpus cases with `-0` inputs, and eight layouts of a 10,000-level nested chain. The published fixture rounds coordinates to hundredths. The other checks compare each unrounded coordinate with `assert.deepStrictEqual`, which compares numbers by `Object.is`, so −0 differs from 0.
